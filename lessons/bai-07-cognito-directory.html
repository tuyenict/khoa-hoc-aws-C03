Sau bài này bạn sẽ

  • Phân biệt ba “thế giới định danh” mà đề SAA-C03 hay trộn lẫn: workforce vào AWS account (IAM Identity Center), customer / app users (Amazon Cognito) và Windows/AD workloads (AWS Directory Service).
  • Hiểu sâu user pool: user directory + OIDC IdP, ba loại token (ID, access, refresh), MFA, federation với Google/Facebook/SAML, Lambda triggers, feature plans Lite / Essentials / Plus.
  • Biết cách user pool tích hợp với Amazon API Gateway, Application Load Balancer, AWS AppSync và kịch bản machine-to-machine (M2M).
  • Hiểu identity pool: đổi token lấy temporary AWS credentials, authenticated vs guest, role-based và attribute-based access control.
  • Chọn đúng loại thư mục của AWS Directory Service: AWS Managed Microsoft AD (Standard/Enterprise, trust, multi-Region), AD Connector (proxy về AD on-premises) và Simple AD (Samba 4).
Nối tiếp Bài 4 – 6

Bài 4–5 đã dạy IAM, STS và các API AssumeRoleWithSAML / AssumeRoleWithWebIdentity; Bài 6 đã dạy IAM Identity Center cho nhân sự truy cập nhiều AWS account. Bài này lấp nốt hai mảnh còn lại của Domain 1: đăng nhập cho người dùng của ứng dụng (Amazon Cognito) và Microsoft Active Directory trên AWS (AWS Directory Service). Ta sẽ không nhắc lại chi tiết STS – chỉ cần nhớ: identity pool là “người gọi” STS thay cho ứng dụng của bạn.

Bức tranh tổng thể: ai đăng nhập, vào đâu?

Cognito user pools – “Who is this user?” (authentication)

Một user pool là một user directory dựa trên chuẩn OpenID Connect (OIDC), dùng để xác thực người dùng và cấp JSON web tokens (JWTs) cho ứng dụng hoặc API của bạn. Hầu hết ứng dụng cần sign-up/sign-in đều bắt đầu ở đây.

Theo tài liệu, user pool có thể đóng hai vai cùng lúc:

  • Standalone IdP / OIDC identity provider cho ứng dụng: tự lưu local users (người dùng tự đăng ký hoặc do admin tạo trực tiếp trong user pool) – user pool là nguồn “chính chủ” (authoritative) cho các user này.
  • Service provider (SP) / relying party trung gian tới IdP bên thứ ba: social (Amazon, Google, Apple, Facebook) hoặc workforce (SAML 2.0, OIDC – vd Okta, AD FS). User pool nhận token/assertion của IdP, gom attributes vào một bộ JWT chuẩn của riêng bạn. Nhờ vậy ứng dụng chỉ cần hiểu một định dạng token. Federated users cũng có profile trong user pool.

Feature plans: Lite, Essentials, Plus

Mỗi user pool chọn một feature plan; chi phí tính theo monthly active users (MAUs) và tính năng dùng. Plan áp cho cả user pool (không tách theo app client); các user pool trong cùng account có thể chọn plan khác nhau, đổi plan bất cứ lúc nào.

Lite

  • Chi phí thấp, cho user pool ít MAU, chỉ cần xác thực cơ bản.
  • Sign-up/sign-in, groups, social/SAML/OIDC federation, M2M, MFA bằng SMS/TOTP, Lambda triggers, user import, classic hosted UI.

Essentials (mặc định)

  • Mọi tính năng xác thực mới nhất: managed login + visual editor.
  • Passwordless (OTP email/SMS), passkey (FIDO2), email MFA, choice-based sign-in, tùy biến access token.

Plus

  • Essentials + threat protection (trước đây gọi là advanced security features).
  • Phát hiện mật khẩu bị lộ (compromised credentials), đăng nhập bất thường (vị trí lạ…) – adaptive authentication; log và export hoạt động người dùng + risk score.

Dùng token của user pool: API Gateway, ALB, AppSync và M2M

Sau khi đăng nhập, ứng dụng nhận token từ user pool. Tài liệu Common Amazon Cognito scenarios liệt kê các cách dùng token này để bảo vệ back-end resources mà không cần identity pool.

Application Load Balancer xác thực người dùng thay ứng dụng

Application Load Balancer có thể offload việc xác thực: listener rule có action authenticate-cognito (user pool) hoặc authenticate-oidc (IdP tương thích OIDC bất kỳ). Những điểm tài liệu ELB nêu rõ:

  • Hai action này chỉ hỗ trợ trên HTTPS listener.
  • App client của user pool phải có client secret, dùng authorization code grant; scope phải trả về ID token (vd openid).
  • ALB gửi session cookie AWSELB cho client; SessionTimeout mặc định 7 ngày (có thể ngắn tới 1 giây). Client phải hoàn tất đăng nhập trong 15 phút, nếu không nhận HTTP 401.
  • ALB chuyển claim tới target qua header x-amzn-oidc-data (JWT có chữ ký ES256 – target nên verify và kiểm tra signer là ARN của ALB), cùng x-amzn-oidc-accesstoken, x-amzn-oidc-identity.
  • OnUnauthenticatedRequest: authenticate (mặc định – chuyển hướng tới IdP), allow (cho qua, không có claim – trang công khai + trang cá nhân hóa), deny (trả 401 – hợp với SPA gọi AJAX).
  • Nếu đặt CloudFront trước ALB: forward toàn bộ header, query string và cookie để không cache phản hồi đã xác thực.

AppSync và machine-to-machine (M2M)

  • AWS AppSync (GraphQL): chế độ AMAZON_COGNITO_USER_POOLS dùng token user pool; hoặc chế độ AWS_IAM dùng credentials từ identity pool.
  • M2M: ứng dụng, dịch vụ, thiết bị IoT tự xác thực bằng app client có client secret và grant client_credentials. Cognito chỉ cấp access token (không có ID token, không có refresh token). Access token mang custom scopes do resource server định nghĩa. Lưu lượng M2M lớn ⇒ cache token (API Gateway cache, ElastiCache, DynamoDB) để tránh chạm quota request của token endpoint.
Mẹo thi (Exam Tip) – bảo vệ API/web
  • “REST API in API Gateway must allow only signed-in users of the mobile app” ⇒ Cognito user pool authorizer trên API Gateway.
  • “Add authentication to an existing web app behind an ALB without changing application code” ⇒ ALB authenticate-cognito / authenticate-oidc (nhớ: HTTPS listener).
  • “IoT devices / microservices call an API without a human user” ⇒ user pool M2M – client credentials grant.

Cognito identity pools – “What AWS resources may this user reach?” (authorization)

Một identity pool là tập hợp các định danh duy nhất (identity ID) gán cho người dùng hoặc khách, được ủy quyền nhận temporary AWS credentials. Identity pool đổi một token đáng tin cậy (từ user pool, social provider, SAML hoặc OIDC provider) lấy credentials tạm thời, quyền tối thiểu từ AWS STS để app gọi trực tiếp Amazon S3, Amazon DynamoDB… thay cho người dùng.

Authenticated vs unauthenticated (guest) identities

Authenticated identities

  • Người dùng đã được xác thực bởi một provider được hỗ trợ: Cognito user pool, Login with Amazon, Sign in with Apple, Facebook, Google, SAML, OIDC, hoặc developer provider (back-end xác thực của riêng bạn – developer-authenticated identities).
  • Nhận credentials của authenticated role (hoặc role chọn theo rule).

Unauthenticated (guest) identities

  • Khách chưa đăng nhập vẫn nhận identity ID và credentials giới hạn – không cần token.
  • Phải bật Guest access và gán unauthenticated role có quyền rất hẹp (vd chỉ đọc catalog sản phẩm, ghi log analytics).

  • Enhanced flow (mặc định) vs basic (classic) flow: basic flow cho phép bỏ qua lựa chọn role của identity pool và tự gọi AssumeRoleWithWebIdentity; phải chủ động bật.
  • Xóa identity khỏi pool ⇒ lần sau user nhận identity ID mới. Đổi application ID của IdP đã liên kết ⇒ user cũ không xác thực được nữa. Xóa identity pool không hoàn tác được.
Mẹo thi (Exam Tip) – identity pool
  • “Mobile app users must upload photos directly to S3; each user can access only their own objects” ⇒ identity pool + IAM policy với ${cognito-identity.amazonaws.com:sub} (hoặc ABAC principal tags).
  • “Allow users to browse the app without signing in, with limited access to AWS resources” ⇒ unauthenticated (guest) identities.
  • “Different permissions for admin vs regular users” ⇒ user pool groups gắn IAM role, identity pool chọn role theo token/rule.
  • Thấy “embed IAM access keys in the app”, “create an IAM user per customer” ⇒ loại ngay.

Bẫy: Cognito ≠ IAM Identity Center

Cả hai đều “SSO” và đều nối được với SAML IdP, nhưng Cognito phục vụ người dùng của ứng dụng (customer identity – CIAM), còn IAM Identity Center phục vụ nhân sự truy cập AWS account và ứng dụng doanh nghiệp. Đề hỏi “employees access the AWS Management Console of 50 accounts” mà chọn Cognito là sai; đề hỏi “2 million customers sign in to our mobile app” mà chọn Identity Center cũng sai.

AWS Directory Service cung cấp nhiều cách dùng Microsoft Active Directory (AD) với các dịch vụ AWS khác. Thư mục lưu thông tin về user, group, thiết bị; admin dùng chúng để quản lý quyền truy cập. Directory Service phục vụ khách hàng muốn đưa ứng dụng Microsoft AD-aware hoặc LDAP-aware lên cloud.

AWS Managed Microsoft AD là gì?

Tên đầy đủ AWS Directory Service for Microsoft Active Directory: Microsoft AD thật được AWS quản lý, chạy trên Windows Server 2019. Dịch vụ tạo một cặp domain controller có tính sẵn sàng cao trong VPC của bạn, ở hai Availability Zone khác nhau; AWS tự lo giám sát host, phục hồi, replicate dữ liệu, snapshot hằng ngày và cập nhật phần mềm. Bạn vẫn quản lý user, group, Group Policy bằng công cụ AD quen thuộc từ một máy Windows đã join domain. Có thể thêm domain controller để scale và phân tải.

Làm được gì?

  • Chạy workload directory-aware: Microsoft SharePoint, SQL Server Always On Availability Groups, ứng dụng .NET.
  • Hỗ trợ dịch vụ AWS: Amazon WorkSpaces, WorkDocs, Amazon QuickSight (Quick), Amazon Chime, Amazon Connect, Amazon RDS for SQL Server (và RDS for Oracle/PostgreSQL), Amazon FSx for Windows File Server, AWS IAM Identity Center.
  • Join EC2 instance vào domain ⇒ người dùng có trải nghiệm Windows SSO giống on-premises. Vì AD là LDAP directory ⇒ dùng được cho Linux SSH authentication và ứng dụng LDAP.
  • Schema extension, fine-grained password policy, secure LDAP (LDAPS) qua SSL/TLS, MFA (qua RADIUS) khi truy cập ứng dụng AWS từ Internet.
  • Đăng nhập AWS Management Console bằng tài khoản AD; kết hợp IAM Identity Center để lấy short-term credentials cho CLI/SDK; thêm Microsoft Entra Connect (+ AD FS) để đăng nhập Office 365.

Trust relationship với AD on-premises

Managed Microsoft AD hỗ trợ trust relationship loại external và forest, theo cả ba hướng: one-way incoming, one-way outgoing và two-way – với AD self-managed (on-premises hoặc trên EC2) hoặc giữa nhiều Managed Microsoft AD với nhau. Mô hình AWS mô tả là resource forest: định danh người dùng ở lại AD hiện có, còn forest trên AWS quản lý tài nguyên AWS – giữ cô lập vận hành mà vẫn SSO liền mạch.

  • Two-way trust bắt buộc cho các AWS Enterprise Apps: Amazon Chime, Amazon Connect, QuickSight, IAM Identity Center, WorkDocs, WorkMail, WorkSpaces và AWS Management Console (Managed AD phải query được user/group ở AD của bạn). Có thể bật selective authentication để chỉ service account của ứng dụng AWS được query.
  • Amazon EC2, Amazon RDS, Amazon FSx hoạt động với one-way hoặc two-way trust.
  • Điều kiện: kết nối mạng giữa on-premises và VPC (Site-to-Site VPN hoặc Direct Connect), mở đúng port AD trên firewall và security group, bật Kerberos pre-authentication, cấu hình DNS conditional forwarder hai phía; NetBIOS/domain name hai bên phải khác nhau.

AD Connector và Simple AD

AD Connector – directory gateway về AD on-premises

AD Connector là một directory gateway (proxy) chuyển hướng yêu cầu thư mục về Microsoft AD on-premises mà không cache bất kỳ thông tin nào trên cloud. Bạn chỉ cần thêm một service account vào AD; không cần đồng bộ thư mục, không cần dựng hạ tầng federation.

  • Hai kích thước: small (tổ chức nhỏ, ít operations/giây) và large (vừa – cao). Không giới hạn số user hay connection; muốn tăng hiệu năng thì dàn tải qua nhiều AD Connector.
  • Dùng được với WorkSpaces, WorkDocs, QuickSight, Chime, Amazon Connect, WorkMail; join EC2 Windows vào domain on-premises bằng seamless domain join; đăng nhập AWS Management Console bằng tài khoản AD (qua IAM role).
  • MFA: tích hợp hạ tầng MFA dựa trên RADIUS hiện có.
  • Giới hạn: không hỗ trợ transitive trust; quan hệ 1-1 với domain (mỗi domain/child domain cần một AD Connector riêng); không chia sẻ được cho account khác; không multi-VPC aware (WorkSpaces phải nằm cùng VPC với AD Connector); không tương thích RDS SQL Server.

Simple AD – thư mục tương thích AD giá rẻ

Simple AD là thư mục độc lập do AWS quản lý, chạy trên Samba 4 Active Directory Compatible Server. AWS lo giám sát, snapshot hằng ngày (point-in-time recovery) và phục hồi.

Có

  • Hai kích thước: Small – tới 500 user (~2.000 objects); Large – tới 5.000 user (~20.000 objects).
  • User account, group membership, Group Policy, join EC2 Linux/Windows vào domain, Kerberos-based SSO, LDAP cho ứng dụng Linux.
  • Dùng với WorkSpaces, WorkDocs, QuickSight, WorkMail; đăng nhập Console qua IAM role.

Không có

  • MFA, trust relationship với domain khác, schema extension, LDAPS, PowerShell AD cmdlets, AD recycle bin, gMSA, FSMO role transfer, DNS dynamic update.
  • Không hỗ trợ RDS for SQL Server/Oracle, Amazon FSx, IAM Identity Center, Chime, WorkSpaces Applications.
Bẫy thường gặp với Directory Service
  • Simple AD không phải Microsoft AD thật – không trust, không MFA. Đề yêu cầu “trust with on-premises AD” hoặc “MFA” ⇒ không chọn Simple AD.
  • AD Connector không lưu user trên AWS – không dùng được làm thư mục độc lập, và phụ thuộc hoàn toàn vào kết nối mạng tới on-premises.
  • Simple AD không còn mở cho khách hàng mới (tài liệu hiện tại); đề cũ vẫn có thể nhắc như phương án “low-cost, small”.
  • Cần dùng chung directory cho nhiều AWS account ⇒ Managed Microsoft AD + directory sharing, không phải AD Connector.

Tóm tắt ghi nhớ

Những điều phải nhớ
  • Cognito = định danh cho người dùng ứng dụng; IAM Identity Center = nhân sự vào AWS account; Directory Service = Microsoft AD trên AWS.
  • User pool = user directory + OIDC IdP + authorization server: sign-up/sign-in, managed login, MFA, social/SAML/OIDC federation, groups, Lambda triggers (trả lời trong 5 giây), M2M. Phát ID, access, refresh token (refresh mặc định 30 ngày, 60 phút – 10 năm).
  • Feature plans: Lite (cơ bản) · Essentials (mặc định, passwordless, passkey, email MFA) · Plus (threat protection, compromised credentials, adaptive auth).
  • Token user pool dùng trực tiếp cho API Gateway authorizer, ALB authenticate-cognito (chỉ HTTPS listener), AppSync.
  • Identity pool = đổi token lấy temporary AWS credentials qua STS; hỗ trợ guest; phân quyền bằng role (default / rule / group) hoặc ABAC principal tags; mẫu ${cognito-identity.amazonaws.com:sub} cho prefix S3 riêng từng user.
  • Managed Microsoft AD: AD thật, 2 DC ở 2 AZ, Standard (~30k objects) / Enterprise (~500k, multi-Region), trust external/forest 1–2 chiều, two-way trust cho WorkSpaces/Identity Center/Console, hỗ trợ RDS SQL Server & FSx, chia sẻ được cho account khác.
  • AD Connector: proxy, không cache, cần VPN/DX, RADIUS MFA, 1-1 với domain, không chia sẻ, không multi-VPC, không RDS SQL Server.
  • Simple AD: Samba 4, 500 / 5.000 user, không trust, không MFA; không mở cho khách mới.

A company is building a mobile app that will have millions of users. Users must be able to sign up, sign in, reset their passwords, and optionally sign in with their Google or Facebook accounts. The company wants the LEAST development and operational effort. Which solution should a solutions architect recommend?
  1. Create an IAM user for each customer and enable MFA.
  2. Use AWS IAM Identity Center with an external identity provider for each social network.
  3. Use an Amazon Cognito user pool with managed login and configure Google and Facebook as social identity providers.
  4. Deploy AWS Managed Microsoft AD and create a user account for each customer.
Đáp án C. User pool là user directory cho ứng dụng: sign-up/sign-in, quên mật khẩu, MFA, managed login có sẵn, và federation với Google/Facebook – scale tới hàng triệu người dùng. A sai: IAM user dành cho định danh quản trị AWS, không cho khách hàng; có quota và không có sign-up. B sai: Identity Center phục vụ workforce truy cập AWS account/ứng dụng doanh nghiệp, không phải CIAM. D sai: Managed AD dành cho workload Windows/AD, giới hạn số object và không hỗ trợ social login; tài liệu nói SaaS scale lớn ⇒ Cognito.
Một công ty đang xây dựng một ứng dụng di động sẽ có hàng triệu người dùng. Người dùng phải có thể đăng ký (sign up), đăng nhập (sign in), đặt lại mật khẩu, và tùy chọn đăng nhập bằng tài khoản Google hoặc Facebook. Công ty muốn LEAST development and operational effort (ít công sức phát triển và vận hành nhất). Solutions architect nên đề xuất giải pháp nào?
  • Tạo một IAM user cho mỗi khách hàng và bật MFA.Sai: IAM user dành cho định danh quản trị AWS, không dành cho khách hàng của ứng dụng; có quota giới hạn và không có chức năng tự đăng ký.
  • Dùng AWS IAM Identity Center với một external identity provider cho mỗi mạng xã hội.Sai: IAM Identity Center phục vụ workforce (nhân viên) truy cập AWS account/ứng dụng doanh nghiệp, không phải quản lý định danh khách hàng (CIAM).
  • Dùng một Amazon Cognito user pool với managed login và cấu hình Google và Facebook làm social identity provider.Đúng: user pool có sẵn sign-up/sign-in, quên mật khẩu, managed login và federation với Google/Facebook, scale tới hàng triệu người dùng mà không phải tự xây.
  • Triển khai AWS Managed Microsoft AD và tạo một user account cho mỗi khách hàng.Sai: Managed AD dành cho workload Windows/AD, giới hạn số object và không hỗ trợ social login.
A photo-sharing mobile app authenticates users with an Amazon Cognito user pool. The app must upload images directly to an Amazon S3 bucket, and each user must be able to access only the objects under a prefix that matches their own identity. The company does not want to embed long-term credentials in the app. What should the solutions architect do?
  1. Configure an Amazon Cognito identity pool that trusts the user pool. Attach an IAM policy to the authenticated role that allows access to the prefix that uses the ${cognito-identity.amazonaws.com:sub} policy variable.
  2. Create an IAM user for the app and store its access keys in the app code. Use a bucket policy to restrict each prefix.
  3. Send the user pool ID token in the Authorization header of each S3 PUT request.
  4. Configure an S3 bucket policy that allows public writes and use object tags to identify the owner.
Đáp án A. Identity pool đổi token user pool lấy temporary AWS credentials qua STS; policy variable identity ID giới hạn mỗi user vào prefix riêng (hoặc dùng ABAC principal tags). B sai: nhúng access key dài hạn vào app là anti-pattern – lộ key là lộ toàn bộ. C sai: S3 không hiểu JWT của user pool; request S3 phải ký SigV4 bằng AWS credentials. D sai: public write là lỗ hổng bảo mật nghiêm trọng.
Một ứng dụng di động chia sẻ ảnh xác thực người dùng bằng một Amazon Cognito user pool.
