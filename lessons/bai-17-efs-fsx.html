Ai mount được EFS?

  • Compute AWS: Amazon EC2, Amazon ECS, Amazon EKS, AWS Lambda, AWS Fargate – EFS là lựa chọn mặc định khi container/hàm serverless cần storage bền và dùng chung.
  • Client khuyến nghị: Linux NFSv4.1 thế hệ mới (Amazon Linux, Amazon Linux 2, Red Hat, Ubuntu, macOS Big Sur) cùng EFS mount helper (amazon-efs-utils).
  • On-premises: server Linux (khuyến nghị kernel ≥ 4.0) mount qua AWS Direct Connect hoặc Site-to-Site VPN. Khuyên mount bằng IP của mount target thay vì DNS name. Không phí thêm cho truy cập từ on-premises (chỉ trả phí Direct Connect/VPN). Use case: migrate dữ liệu lên EFS, cloud bursting, backup dữ liệu on-premises.
  • VPC/account khác: client có thể kết nối tới mount target ở account hoặc VPC khác (VPC peering, Transit Gateway).
  • Không hỗ trợ Windows: tài liệu ghi rõ “Using Amazon EFS with Microsoft Windows–based Amazon EC2 instances is not supported” ⇒ Windows cần FSx for Windows (hoặc FSx for ONTAP).

Mount target – “cửa vào” của EFS trong VPC

Để truy cập EFS trong VPC, bạn tạo mount target. Mỗi mount target cung cấp một địa chỉ IP cho endpoint NFSv4. Bạn mount bằng DNS name của file system; DNS này phân giải ra IP của mount target trong cùng AZ với EC2 instance.

  • Tối đa 1 mount target mỗi AZ cho một file system. Nếu AZ có nhiều subnet, chọn một subnet; mọi instance trong AZ dùng chung mount target đó.
  • Một file system chỉ có mount target trong 1 VPC tại một thời điểm; tối đa 1.400 mount target mỗi VPC; mỗi mount target gắn tối đa 5 security group.
  • Security group của mount target phải cho phép inbound TCP 2049 (NFS) từ security group của client (hoặc CIDR on-premises).
  • Mount target được thiết kế highly available; IP và DNS của mount target trong mỗi AZ là tĩnh.
  • Khuyến nghị truy cập mount target cùng AZ để tốt cho hiệu năng và chi phí: với One Zone, instance ở AZ khác sẽ trả phí truyền dữ liệu giữa AZ.

  • EFS cung cấp close-to-open consistency như NFS. Với Regional, write được lưu bền trên nhiều AZ khi ứng dụng ghi đồng bộ (O_DIRECT, fsync) hoặc khi đóng file. Ứng dụng truy cập đồng bộ, ghi không-append có read-after-write consistency.

Mẹo thi (Exam Tip) – nhận diện EFS
  • “Shared file system”, “mounted concurrently by multiple EC2 instances across multiple AZs”, “Linux”, “POSIX-compliant”, “grows and shrinks automatically” ⇒ Amazon EFS.
  • “Auto Scaling group of web servers must share the same content / uploaded files” ⇒ EFS (không phải EBS – EBS gắn với 1 AZ; không phải S3 nếu ứng dụng cần đường dẫn file).
  • “Lambda functions / Fargate tasks need persistent shared storage” ⇒ EFS (Lambda chỉ có /tmp tạm thời).
  • “Cost-effective, data can be re-created, single AZ is acceptable” ⇒ EFS One Zone (+ lifecycle sang IA).
Bẫy thường gặp – EFS
  • Đề có Windows instance cần file share ⇒ không chọn EFS (không hỗ trợ Windows). Chọn FSx for Windows File Server.
  • Mount bị “timed out” ⇒ thường do security group của mount target chưa mở TCP 2049 từ client, hoặc AZ của client chưa có mount target.
  • EFS không phải “ổ đĩa local”: mỗi thao tác đi qua mạng – workload cần độ trễ micro giây cho DB nên dùng EBS io2 / instance store (Bài 11).

EFS performance mode & throughput mode

Hiệu năng file system được đo bằng ba chiều: latency, throughput và IOPS. Với EFS, ba yếu tố cấu hình quyết định hiệu năng: file system type (Regional / One Zone), performance mode (General Purpose / Max I/O) và throughput mode (Elastic / Provisioned / Bursting). AWS khuyến nghị dùng mặc định: General Purpose + Elastic.

Performance mode

General Purpose (mặc định)

  • Độ trễ mỗi thao tác thấp nhất.
  • Lý tưởng cho ứng dụng nhạy độ trễ: web serving, CMS, home directory, file serving chung.
  • One Zone luôn dùng General Purpose.
  • Tới 250.000 thao tác file/giây; theo dõi metric PercentIOLimit.
  • AWS: “luôn dùng General Purpose để có hiệu năng nhanh hơn”.

Max I/O (thế hệ trước)

  • Thiết kế cho workload song song cực lớn chịu được độ trễ cao hơn.
  • Độ trễ mỗi thao tác cao hơn General Purpose.
  • Không hỗ trợ One Zone và không dùng được với Elastic throughput.
  • Đề cũ hay chọn Max I/O cho “big data, thousands of instances”; tài liệu hiện nay khuyên General Purpose + Elastic.

Throughput mode

IOPS không tính phí riêng – được gộp vào throughput: mỗi request NFS được tính là 4 KB throughput hoặc kích thước thực, lấy giá trị lớn hơn. Throughput đọc được “giảm giá” (đọc được tính bằng 1/3 so với ghi), nên đọc đạt cao hơn ghi. Tổng đọc + ghi tối đa 100% giới hạn (vd dùng 33% giới hạn đọc ⇒ còn tối đa 67% giới hạn ghi).

Ví dụ Bursting: vì sao file system nhỏ bị “nghẹt”?

  1. 100 GiB trong lớp Standard ⇒ baseline 5 MiBps (ghi; đọc tới 15 MiBps nhờ tỷ lệ 1/3).
  2. Nghỉ 24 giờ tích được 5 MiB × 86.400 s = 432.000 MiB credit.
  3. Credit đủ burst ở 100 MiBps trong 72 phút mỗi ngày. Hết credit ⇒ rơi về baseline (tối thiểu 1 MiBps).
  4. File system > 1 TiB luôn burst được tới 50% thời gian nếu 50% còn lại nhàn rỗi; credit tối đa 2,1 TiB (hoặc 2,1 TiB mỗi TiB) ⇒ burst liên tục tới 12 giờ.
  5. Cách “cũ” để tăng throughput là chép file rác cho to dung lượng – đừng chọn; đáp án đúng là chuyển sang Elastic (spiky) hoặc Provisioned (ổn định, biết trước).
Hạn chế khi đổi throughput mode

Đổi mode được bất kỳ lúc nào, nhưng sau khi chuyển sang Provisioned hoặc thay đổi mức Provisioned thì trong 24 giờ không được: chuyển từ Provisioned về Elastic/Bursting, hoặc giảm mức Provisioned. Nếu file system có lifecycle policy chuyển dữ liệu sang Archive thì không đổi được sang Bursting/Provisioned (Archive yêu cầu Elastic).

Mẹo thi (Exam Tip) – Throughput
  • “EFS file system is small but the application needs high throughput; BurstCreditBalance keeps dropping to zero” ⇒ Elastic throughput (nếu spiky) hoặc Provisioned throughput (nếu nhu cầu ổn định, biết trước).
  • “Unpredictable, spiky workload, pay only for what you use” ⇒ Elastic.
  • “Latency-sensitive web serving / CMS” ⇒ General Purpose performance mode.
  • Metric cần nhớ: PercentIOLimit (General Purpose gần chạm trần IOPS), BurstCreditBalance (Bursting), MeteredIOBytes (Elastic – đặt cảnh báo chi phí).

EFS: bảo mật, access point, backup & replication

Truy cập của NFS client vào EFS được kiểm soát bằng cả IAM policy và chính sách mạng (security group), cộng thêm quyền POSIX ở cấp file. Dữ liệu được bảo vệ bằng mã hóa, AWS Backup và replication liên Region.

Network: security group

Lớp mạng

IAM authorization for NFS clients

Phân quyền NFS bằng IAM

Điểm truy cập EFS

Điểm vào riêng cho từng ứng dụng: ép POSIX user/group và thư mục gốc riêng. Tối đa 10.000 access point/file system (tăng được).

Encryption

Mã hóa

At rest: bật khi tạo file system, mã hóa cả dữ liệu và metadata bằng KMS. In transit: bật khi mount (TLS qua mount helper).

AWS Backup

Sao lưu tập trung

Backup tăng dần, EFS ưu tiên thao tác file system hơn backup. One Zone được tự động backup. Học sâu ở Bài 19.

EFS Replication

Sao chép file system

Tự động, liên tục sao chép dữ liệu + metadata sang file system đích ở Region bạn chọn; RPO và RTO tính bằng phút.

EFS Access Points – mẫu hay gặp với container và Lambda

EFS access point là điểm vào theo ứng dụng của một file system. Mọi request NFS qua access point được gán một POSIX identity cố định (UID/GID do access point quy định, bất kể client tự xưng là ai) và bị giới hạn trong một root directory riêng (tự tạo thư mục với owner/permission định sẵn nếu chưa có). Kết hợp với IAM policy điều kiện theo ARN access point, bạn cho mỗi ứng dụng/tenant chỉ thấy “thư mục của mình” trên cùng một file system. Lambda và ECS/EKS (EFS CSI driver) thường mount EFS qua access point.

Chi tiết cơ chế ép POSIX identity / root directory, action IAM ClientMount/ClientWrite/ClientRootAccess và tùy chọn mount TLS là kiến thức phổ biến về EFS; các trang tài liệu đã đọc nêu hạn mức 10.000 access point và 20.000 ký tự cho file system policy.

Mẹo thi (Exam Tip) – Bảo mật & DR cho EFS
  • “Existing unencrypted EFS file system must be encrypted at rest” ⇒ tạo file system mới có encryption rồi chép dữ liệu sang (vd bằng AWS DataSync) – encryption at rest chỉ chọn được lúc tạo.
  • “Encrypt data in transit between EC2 and EFS” ⇒ mount bằng EFS mount helper với tùy chọn TLS.
  • “Multiple applications share one EFS, each must only access its own directory with a specific POSIX user” ⇒ EFS access points + IAM authorization.
  • “Disaster recovery to another Region with RPO of minutes for a file system” ⇒ EFS Replication. “Centralized, scheduled backups with retention” ⇒ AWS Backup.
  • “Migrate a large on-premises NFS dataset to EFS” ⇒ AWS DataSync (trang quota EFS khuyến nghị DataSync cho dataset lớn).

Thành phần và tính năng chính

  • File system = một hoặc nhiều Windows file server + storage volume. Khi tạo, bạn chỉ định storage capacity (GiB), SSD IOPS và throughput capacity (MBps) – cả ba thay đổi được sau này (tăng dung lượng, đổi HDD → SSD, tăng/giảm throughput).
  • File share: thư mục chia sẻ qua SMB; có sẵn share mặc định \share, tạo thêm bằng công cụ Shared Folders. Truy cập qua DNS name của file system hoặc DNS alias (giữ nguyên tên \\fileserver cũ khi migrate).
  • Active Directory: file system bắt buộc join vào Microsoft AD khi tạo – AWS Managed Microsoft AD hoặc self-managed AD on-premises (Bài 7). User xác thực bằng AD, quyền cấp file/folder bằng Windows ACL.
  • Tính năng Windows native: DFS Namespaces (gom nhiều file system dưới một namespace chung), DFS Replication (Single-AZ 1), Shadow Copies (người dùng tự khôi phục phiên bản trước của file), Data Deduplication, user quotas, continuously available (CA) shares cho SQL Server.
  • SMB Multichannel: một client có thể đạt nhiều GBps và hàng trăm nghìn IOPS.
  • Client: EC2, Amazon WorkSpaces, AppStream 2.0, VMware Cloud on AWS; on-premises qua Direct Connect hoặc Site-to-Site VPN; VPC/account/Region khác qua VPC peering hoặc Transit Gateway.
  • Không truy cập từ Internet công cộng: nếu Elastic IP bị gắn vào ENI của file system, FSx tự động gỡ ra.

SSD vs HDD

SSD

  • Workload hiệu năng cao nhất, nhạy độ trễ: database (SQL Server), media processing, data analytics.
  • Mặc định 3.000 IOPS và 750 MBps disk throughput mỗi TiB; provision thêm tới 500 IOPS/GiB, 400.000 IOPS mỗi file system.
  • Hỗ trợ mọi deployment type.

HDD

  • Chi phí thấp cho home directories, share phòng ban, CMS.
  • 12 MBps baseline, 80 MBps burst mỗi TiB (burst bucket); dữ liệu nóng được phục vụ từ in-memory cache của file server.
  • Chỉ có ở Single-AZ 2 và Multi-AZ.

Amazon FSx for Lustre

Lustre là file system song song được thiết kế cho những máy tính nhanh nhất thế giới. FSx for Lustre đưa nó thành dịch vụ fully managed cho workload “tốc độ là tất cả”: machine learning, HPC (high performance computing), xử lý video, mô hình tài chính, EDA. Độ trễ sub-millisecond, throughput tới nhiều TBps, hàng triệu IOPS. FSx for Lustre POSIX-compliant, chạy với ứng dụng Linux có sẵn không cần sửa, có read-after-write consistency và file locking.

Tích hợp Amazon S3 – điểm thi quan trọng nhất

Liên kết file system với S3 bucket bằng data repository association (DRA): FSx for Lustre trình bày object S3 thành file. Metadata (danh sách file) được import khi tạo liên kết; nội dung file được nạp từ S3 khi được truy cập lần đầu (lazy loading). Kết quả xử lý được ghi ngược về S3.

  • Automatic import: tự import metadata khi object được tạo/sửa/xóa trong S3 – chỉ cùng Region. Dùng song song được với import data repository task.
  • Automatic export: tự export file và metadata về S3 khi file thay đổi – hỗ trợ cross-Region. Không dùng đồng thời với export data repository task.
  • Cả hai hỗ trợ cross-account. DRA/automatic export không có trên Scratch 1 (và Lustre 2.10).
  • Data repository tasks: import, export, release (giải phóng file đã export để tiết kiệm dung lượng).
  • File system đã liên kết S3 không hỗ trợ backup FSx – S3 đóng vai trò kho dữ liệu bền. Đừng xóa bucket trước khi gỡ liên kết.
  • Cloud bursting từ on-premises: copy dữ liệu qua Direct Connect/VPN, chạy compute trên AWS.
Mẹo thi (Exam Tip) – FSx for Lustre
  • “High performance computing”, “machine learning training”, “sub-millisecond latency, hundreds of GBps”, “parallel file system”, “Linux cluster” ⇒ FSx for Lustre.
  • “Process data stored in S3 with a high-performance file system, write results back to S3” ⇒ FSx for Lustre linked to S3 (data repository association).
  • “Short-term processing, data can be regenerated from S3, lowest cost” ⇒ Scratch. “Long-running, must tolerate file server failure” ⇒ Persistent.
  • “Speed up SageMaker training jobs that read the same S3 dataset repeatedly” ⇒ FSx for Lustre làm input data source.

File system có SSD tier (provision, hiệu năng cao, cho phần dữ liệu đang hoạt động) và capacity pool tier (đàn hồi hoàn toàn tới petabyte, tối ưu chi phí cho dữ liệu ít truy cập). Volume được thin provisioned; mỗi volume chọn một tiering policy:

Tính năng NetApp “mang theo” lên AWS

  • Snapshot (thư mục .snapshot, người dùng tự khôi phục file), FlexClone (clone volume tức thì, chỉ tốn dung lượng phần thay đổi – tạo môi trường dev/test từ dữ liệu production).
  • SnapMirror: replication theo lịch giữa các file system ONTAP – từ NetApp on-premises lên AWS hoặc cross-Region DR. FlexCache: cache on-premises.
  • Storage efficiency: compression, compaction, deduplication theo volume (không bật mặc định); tiết kiệm được giữ nguyên khi xuống capacity pool và trong backup.
  • Bảo mật: mã hóa at rest bằng KMS; in transit bằng SMB Kerberos, IPsec, mã hóa Nitro; antivirus scanning on-demand; xác thực bằng Microsoft AD; file access auditing; NetApp SnapLock WORM (Compliance / Enterprise).
  • Quản lý bằng console/CLI/SDK của AWS hoặc NetApp ONTAP CLI, REST API, NetApp Console. Backup tự động hằng ngày.
  • Volume có thể gắn S3 Access Point để thao tác dữ liệu bằng S3 API (đã nhắc ở Bài 16).

  • “Same dataset must be accessed by Linux (NFS) and Windows (SMB) clients” hoặc “needs iSCSI block storage and file shares” ⇒ FSx for ONTAP (multi-protocol).
  • “Automatically move infrequently accessed data to lower-cost storage while keeping SSD performance for active data” trên file system đa giao thức ⇒ ONTAP capacity pool + tiering policy Auto.

Tóm tắt ghi nhớ

Key takeaways
  • EFS: serverless, đàn hồi tới PB, NFSv4.0/4.1, chỉ Linux (không Windows); mount qua mount target (1/AZ, SG mở TCP 2049); dùng được từ EC2, ECS, EKS, Lambda, Fargate và on-premises (Direct Connect/VPN).
  • Regional (≥ 3 AZ, 99,99%) vs One Zone (1 AZ, 99,9%, rẻ hơn, tự backup); cả hai 11 số 9 độ bền thiết kế.
  • Performance mode: General Purpose (mặc định, khuyến nghị) vs Max I/O (thế hệ trước, độ trễ cao, không dùng với Elastic/One Zone).
  • Throughput mode: Elastic (spiky, trả theo I/O), Provisioned (biết trước, độc lập dung lượng), Bursting (50 KiBps/GiB baseline, burst 100 MiBps/TiB theo credit).
  • Storage class: Standard → IA (mặc định 30 ngày) → Archive (mặc định 90 ngày, tối thiểu 90 ngày, cần Elastic); IA/Archive tính tối thiểu 128 KiB/file; “On first access” đưa về Standard.
  • EFS security: SG + IAM authorization + file system policy + access points (POSIX identity, root directory); encryption at rest chọn lúc tạo, in transit bằng TLS khi mount; Replication sang Region khác RPO/RTO phút.
  • FSx for Windows: SMB, Active Directory bắt buộc, Windows ACL, DFS, Shadow Copies, Dedup; Multi-AZ failover < 30 giây (khuyến nghị cho production); SSD hoặc HDD.
  • FSx for Lustre: HPC/ML, sub-ms, TBps; Scratch (tạm, không replication, burst 6×) vs Persistent (replication trong AZ); liên kết S3 qua data repository association (lazy load, auto import/export).
  • FSx for ONTAP: NFS + SMB + iSCSI + NVMe/TCP, Linux/Windows/macOS; SSD tier + capacity pool (tiering Auto/Snapshot Only/All/None); SnapMirror, FlexClone, dedup/nén tới 65%.
  • FSx for OpenZFS: NFS v3–v4.2, tới 2 triệu IOPS, độ trễ vài trăm µs, snapshot/clone tức thì; migrate ZFS/Linux file server.

Thuật ngữ (Glossary)

File storage / Shared file system
Lưu trữ tệp / Hệ thống tệp dùng chung – lưu dữ liệu dạng thư mục–tệp, nhiều client mount đồng thời.
NFS (Network File System)
Hệ thống tệp mạng – giao thức chia sẻ file chuẩn của Linux/Unix; EFS dùng NFSv4.0/4.1.
SMB (Server Message Block)
Giao thức chia sẻ tệp của Windows – FSx for Windows hỗ trợ SMB 2.0–3.1.1.
POSIX permissions
Quyền POSIX – quyền owner/group/other theo UID/GID của Linux.
Mount target
Điểm gắn kết – ENI có IP trong subnet để client mount EFS; tối đa 1 mỗi AZ.
Regional / One Zone file system
Hệ thống tệp đa vùng / một vùng sẵn sàng – lưu dữ liệu trên ≥ 3 AZ hoặc 1 AZ.
Performance mode (General Purpose / Max I/O)
Chế độ hiệu năng – độ trễ thấp nhất (mặc định) / song song cao, độ trễ cao hơn (thế hệ trước).
Throughput mode (Elastic / Provisioned / Bursting)
Chế độ thông lượng – tự co giãn / cấp phát trước / theo dung lượng và burst credit.
Burst credits
Tín dụng bùng nổ – tích lũy khi dùng dưới baseline, tiêu khi vượt baseline.
EFS Infrequent Access (IA) / EFS Archive
Lớp truy cập không thường xuyên / Lớp lưu trữ dài hạn – rẻ hơn Standard, độ trễ hàng chục ms, tối thiểu 128 KiB/file.
Lifecycle management (EFS)
Quản lý vòng đời – tự chuyển file giữa Standard/IA/Archive theo thời gian kể từ lần truy cập cuối.
EFS Access Point
Điểm truy cập EFS – điểm vào theo ứng dụng, ép POSIX user/group và thư mục gốc.
File system policy
Chính sách hệ thống tệp – resource-based IAM policy gắn vào EFS.
EFS Replication
Sao chép hệ thống tệp EFS – liên tục sang Region khác, RPO/RTO tính bằng phút.
Cloud bursting
Bùng nổ lên đám mây – đẩy phần tải tính toán từ on-premises lên AWS khi cần.
Multi-AZ / Single-AZ deployment (FSx)
Triển khai đa AZ / một AZ – có hoặc không có file server standby ở AZ khác.
Preferred / Standby file server
Máy chủ tệp ưu tiên / dự phòng – cặp server trong FSx for Windows Multi-AZ.
DFS Namespaces
Không gian tên DFS – gom nhiều file share dưới một đường dẫn chung.
Shadow Copies
Bản sao bóng – snapshot Windows cho phép user khôi phục phiên bản trước của file.
Data Deduplication
Khử trùng lặp dữ liệu – lưu một lần các khối dữ liệu trùng để giảm dung lượng.
Continuously available (CA) share
Share khả dụng liên tục – SMB share cho SQL Server HA.
Lustre / Parallel file system
Hệ thống tệp song song – dữ liệu phân tán trên nhiều storage server, phục vụ HPC.
Scratch / Persistent file system
Hệ thống tệp tạm / bền – không nhân bản dữ liệu / nhân bản và tự thay server hỏng.
Data repository association (DRA)
Liên kết kho dữ liệu – nối thư mục FSx for Lustre với S3 bucket/prefix.
Lazy loading
Nạp lười – nội dung file được nạp từ S3 khi truy cập lần đầu.
Capacity pool tier
Tầng lưu trữ đàn hồi giá rẻ – tier của FSx for ONTAP cho dữ liệu lạnh.
Tiering policy / Cooling period
Chính sách phân tầng / Thời gian nguội – quyết định khi nào dữ liệu ONTAP xuống capacity pool.
SnapMirror / FlexClone / SnapLock
Sao chép NetApp / Bản sao volume tức thì / Khóa WORM của NetApp.
iSCSI / NVMe over TCP
Giao thức block storage qua mạng IP – FSx for ONTAP cung cấp LUN/namespace cho server.
Thin provisioning
Cấp phát mỏng – chỉ tiêu dung lượng thật khi dữ liệu được ghi.

  4. An instance store volume on each instance synchronized with rsync.
Đáp án C. EFS Regional là file system NFS dùng chung cho Linux, lưu dư thừa trên nhiều AZ, tự co giãn không cần provision; mỗi AZ có một mount target. A sai: EBS Multi-Attach chỉ trong một AZ và cần clustered file system (Bài 11). B sai: FSx for Windows dùng SMB + AD, cần provision dung lượng – không phù hợp Linux CMS và nhiều vận hành hơn. D sai: instance store mất dữ liệu khi stop, tự đồng bộ tốn vận hành.
Một công ty chạy hệ thống quản lý nội dung (CMS) trên các Linux EC2 instance trong một Auto Scaling group trải trên ba Availability Zone. Mọi instance phải đọc và ghi cùng một tập file được tải lên, và dung lượng lưu trữ phải tự động tăng khi có thêm nội dung. Giải pháp lưu trữ nào đáp ứng các yêu cầu này với LEAST operational overhead (ít công sức vận hành nhất)?

  • Một instance store volume trên mỗi instance, đồng bộ bằng rsync.Sai: instance store mất dữ liệu khi instance stop/terminate, và tự đồng bộ bằng rsync tốn nhiều công vận hành, dễ lệch dữ liệu.
