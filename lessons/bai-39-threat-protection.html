Bức tranh tổng thể: bảo vệ, phát hiện và điều tra

Bảo mật trên AWS theo nguyên tắc defense in depth: không dựa vào một lớp duy nhất. Ở vành đai (perimeter) – nơi traffic từ Internet đi vào lần đầu – ta chặn tấn công bằng AWS Shield (DDoS) và AWS WAF (tấn công tầng ứng dụng HTTP/S), quản lý tập trung bằng AWS Firewall Manager. Bên trong môi trường, ta phát hiện hoạt động đáng ngờ (GuardDuty), đánh giá lỗ hổng phần mềm (Inspector), tìm dữ liệu nhạy cảm (Macie), tổng hợp & chấm điểm tuân thủ (Security Hub CSPM) và điều tra nguyên nhân gốc (Detective).

AWS WAF

Tường lửa ứng dụng web (Layer 7)

Dịch vụ chống DDoS được quản lý

AWS Firewall Manager

AWS WAF: web ACL, rule và rule group

AWS WAF cho phép giám sát các request HTTP(S) được chuyển tới tài nguyên web được bảo vệ. Dựa trên tiêu chí bạn đặt (IP nguồn, giá trị query string, header, quốc gia…), dịch vụ gắn với tài nguyên sẽ trả về nội dung, trả mã HTTP 403 (Forbidden), hoặc một custom response. WAF làm việc ở Layer 7 – nó hiểu HTTP, khác với Security Group/NACL (Layer 3/4, Bài 21).

Tài nguyên được WAF bảo vệ

  • Application Load Balancer

  • Muốn bảo vệ app trên ECS: đặt sau ALB đã bật WAF (tài liệu ghi rõ)

Các thành phần

  • Web ACL (trên console mới gọi là protection pack): tài nguyên WAF dùng để bảo vệ một tập tài nguyên AWS. Chứa các rule và một default action (Allow hoặc Block) cho request không bị rule nào allow/block rõ ràng.
  • Rule: một statement (tiêu chí kiểm tra) + một action. Rule không phải tài nguyên riêng – chỉ tồn tại trong web ACL hoặc rule group.
  • Rule group: tập rule tái sử dụng. Có 3 nguồn: AWS Managed Rules, AWS Marketplace (seller bên thứ ba), và rule group tự viết. Mỗi rule group có capacity cố định (immutable) đặt lúc tạo.
  • Web ACL capacity unit (WCU): đơn vị đo tài nguyên xử lý của rule. Rule đơn giản (geo match = 1 WCU) tốn ít, rule phức tạp (regex, transformation, kiểm tra JSON body) tốn nhiều.
  • Thứ tự ưu tiên (priority): WAF đánh giá rule từ trên xuống theo số priority; rule có terminating action (Allow/Block) khớp đầu tiên sẽ dừng việc đánh giá.

AWS Managed Rules

Các rule group do AWS viết và cập nhật, chọn version được, override action từng rule được, thu hẹp phạm vi bằng scope-down statement. Tất cả đều gắn label cho request khớp.

  • Baseline: Core rule set (CRS) – các lỗ hổng web phổ biến (kiểu OWASP); Admin protection – chặn truy cập trang quản trị lộ ra ngoài; Known bad inputs – pattern request không hợp lệ/khai thác đã biết.
  • Use-case specific: SQL database, Linux OS, POSIX OS, Windows OS, PHP application, WordPress application.
  • IP reputation: Amazon IP reputation list (IP do Amazon threat intelligence đánh dấu xấu), Anonymous IP list (VPN, proxy, Tor, hosting – che giấu danh tính).
  • Intelligent threat mitigation (có phí thêm): Bot Control (bot thông thường và bot nhắm mục tiêu), Fraud Control ATP (account takeover prevention – chống chiếm tài khoản qua trang login, credential stuffing), Fraud Control ACFP (account creation fraud prevention – chống tạo tài khoản giả), Anti-DDoS (DDoS tầng 7).

Phạm vi (scope), ghi log và giám sát

  • Web ACL cho CloudFront có phạm vi Global và Region bị cố định là US East (N. Virginia) us-east-1. Web ACL cho tài nguyên Regional (ALB, API Gateway, AppSync, Cognito…) phải tạo cùng Region với tài nguyên đó.
  • Mỗi tài nguyên chỉ gắn được một web ACL; một web ACL có thể gắn nhiều tài nguyên (kiến thức phổ biến).
  • Log đầy đủ request (logging configuration): gửi tới CloudWatch Logs, Amazon S3 hoặc Amazon Data Firehose. Tên đích phải bắt đầu bằng aws-waf-logs- (kiến thức phổ biến). Ngoài ra WAF có CloudWatch metrics và sampled requests trên console.
  • Quy trình triển khai an toàn theo tài liệu: test/tune trong môi trường staging ⇒ chạy rule ở Count mode với traffic production ⇒ rồi mới bật Block.
  • CloudFront geo restriction (Bài 25) không chuyển request bị chặn tới WAF. Nếu cần chặn theo địa lý kết hợp tiêu chí khác (vd chặn quốc gia X trừ một số IP) ⇒ dùng WAF geo match thay cho geo restriction.

Rate-based rule – giới hạn tốc độ request

Rate-based rule đếm request đến, gom theo tiêu chí bạn chọn, và áp action (thường là Block) khi một nhóm vượt ngưỡng trong evaluation window. Đây là công cụ chính chống HTTP flood, brute-force login và scraping.

  • Request aggregation: theo IP nguồn, theo IP trong header (vd X-Forwarded-For – WAF lấy IP đầu tiên trong header, hữu ích khi đứng sau proxy/CDN khác), custom keys (kết hợp header, cookie, query, URI path, label…) hoặc Count all (đếm tất cả – bắt buộc có scope-down statement).
  • Scope-down statement: chỉ đếm request khớp điều kiện, vd chỉ đếm request tới /login, hay chỉ request từ một quốc gia.
  • Action: mọi action trừ Allow. Rate limit được áp “gần đúng”, không bảo đảm chính xác tuyệt đối.
  • Mỗi lần dùng rule (trong web ACL khác nhau, hay rule group dùng ở nhiều nơi) là một instance riêng, đếm riêng.
  • Rate-based statement không lồng được trong statement khác.
Mẹo thi (Exam Tip)
  • “Protect a web application on ALB/CloudFront/API Gateway from SQL injection and XSS” ⇒ AWS WAF + AWS Managed Rules (Core rule set, SQL database). Không phải Shield, GuardDuty hay Security Group.
  • “A single IP sends thousands of requests”, “HTTP flood”, “brute-force login” ⇒ WAF rate-based rule (có thể scope-down vào /login).
  • “Block traffic from specific countries but allow a partner IP range” ⇒ WAF rule: AND(geo match, NOT(IP set)).
  • “Web ACL for CloudFront not visible” ⇒ web ACL phải ở phạm vi Global (us-east-1).
  • “Application behind a Network Load Balancer needs WAF” ⇒ NLB không hỗ trợ WAF: đổi sang ALB hoặc đặt CloudFront + WAF phía trước.
  • “Test new rules without impacting users” ⇒ đặt rule ở Count và xem metric/log.

AWS Shield: chống DDoS Standard vs Advanced

Distributed Denial of Service (DDoS) là tấn công dùng nhiều nguồn cùng lúc làm cạn tài nguyên khiến ứng dụng không phục vụ được người dùng thật. AWS Shield là dịch vụ chống DDoS được quản lý, bảo vệ application perimeter. Nếu người dùng vào thẳng Region, vành đai là VPC; nếu đi qua Route 53 rồi CloudFront hoặc Global Accelerator, vành đai bắt đầu ngay tại edge của mạng AWS – xa ứng dụng hơn, hấp thụ tấn công tốt hơn.

Shield Standard

  • Tự động cho mọi khách hàng AWS, không tốn thêm phí, không cần bật.
  • Chống các tấn công DDoS phổ biến, thường gặp ở tầng mạng và vận chuyển (Layer 3/4): SYN flood, UDP reflection…
  • Lợi ích đặc biệt với Route 53 hosted zone, CloudFront, Global Accelerator standard accelerator: được bảo vệ toàn diện trước mọi tấn công L3/L4 đã biết.
  • Không có đội hỗ trợ riêng, không bồi hoàn chi phí, không có metric tấn công chi tiết.

Shield Advanced

  • Trả phí (subscription); chỉ bảo vệ tài nguyên bạn chỉ định rõ (hoặc qua chính sách Firewall Manager) – không tự động.
  • Bảo vệ mở rộng trước DDoS, volumetric bot, khai thác lỗ hổng; cả L3/L4 và L7.
  • Shield Response Team (SRT), proactive engagement, cost protection, health-based detection, automatic application layer DDoS mitigation, protection groups, metric & báo cáo chi tiết.
  • Bao gồm phí WAF chuẩn cho tài nguyên được bảo vệ.

Tài nguyên Shield Advanced bảo vệ được

  • Amazon CloudFront distribution (kể cả staging distribution của continuous deployment).
  • Amazon Route 53 hosted zone.
  • AWS Global Accelerator standard accelerator.
  • Elastic IP của EC2 ⇒ bảo vệ EC2 instance và Network Load Balancer thông qua Elastic IP gắn với chúng.
  • Application Load Balancer và Classic Load Balancer.

Kiến trúc chống DDoS (DDoS resiliency)

Shield bảo vệ mọi ứng dụng trên AWS, nhưng tài liệu nhấn mạnh quyết định kiến trúc của bạn ảnh hưởng tới khả năng chịu DDoS. Các best practice (tổng hợp từ tài liệu và whitepaper DDoS best practices – kiến thức phổ biến):

  1. Đưa vành đai ra edge: phục vụ qua CloudFront (nội dung tĩnh và động) và Route 53; với TCP/UDP không phải HTTP ⇒ Global Accelerator. Mạng edge toàn cầu hấp thụ tấn công volumetric.
  2. Giảm bề mặt tấn công: backend trong private subnet, chỉ ALB/CloudFront public; Security Group chỉ cho origin nhận traffic từ CloudFront (managed prefix list) hoặc ALB.
  3. Lọc tầng 7 bằng WAF (rate-based rule, managed rules, geo, IP reputation) trên CloudFront/ALB.
  4. Hấp thụ bằng scale: ALB + Auto Scaling để chịu tải tăng đột biến trong khi mitigation hoạt động.
  5. Giám sát: CloudWatch alarm cho metric bất thường; với ứng dụng quan trọng ⇒ Shield Advanced + health check + proactive engagement.
Mẹo thi (Exam Tip)
  • “Protect against DDoS at no additional cost” ⇒ Shield Standard (đã bật sẵn) + CloudFront/Route 53.
  • “24/7 access to AWS DDoS experts”, “reimburse scaling charges caused by a DDoS attack”, “near real-time attack visibility” ⇒ Shield Advanced.
  • “Automatically mitigate layer 7 DDoS with minimal effort” ⇒ Shield Advanced automatic application layer DDoS mitigation (cần web ACL WAF gắn với tài nguyên).
  • “Protect an EC2 instance / NLB with Shield Advanced” ⇒ bảo vệ qua Elastic IP.
  • “Subscribe all accounts in the organization to Shield Advanced and protect new resources automatically” ⇒ Firewall Manager Shield Advanced policy.

AWS Firewall Manager đơn giản hóa việc quản trị nhiều loại bảo vệ trên nhiều account và tài nguyên: bạn thiết lập một lần, dịch vụ tự động áp lên các account và tài nguyên – kể cả account và tài nguyên thêm vào sau. Amazon GuardDuty: phát hiện mối đe dọa thông minh

Amazon GuardDuty liên tục giám sát, phân tích các nguồn dữ liệu và log trong môi trường AWS. Nó dùng threat intelligence feeds (danh sách IP, domain độc hại, file hash) và machine learning để nhận diện hoạt động đáng ngờ, rồi sinh finding. Với các nguồn nền tảng, chỉ cần bật GuardDuty là chạy – không cài agent, không cấu hình log.

Các kịch bản GuardDuty phát hiện (theo tài liệu)

  • Credential AWS bị lộ / bị đánh cắp (compromised and exfiltrated credentials).
  • Data exfiltration và phá hủy dữ liệu có thể dẫn tới ransomware; đăng nhập bất thường vào Aurora/RDS.
  • Cryptomining trái phép trên EC2 và container.
  • Malware trong EC2, container, và file mới upload lên S3.
  • Sự kiện cấp OS, mạng, file bất thường trên EKS, ECS-Fargate, EC2.

Nguồn dữ liệu nền tảng (foundational data sources)

  • Log được mã hóa khi truyền; GuardDuty trích trường cần thiết để profiling rồi loại bỏ log. Việc truy cập các nguồn nền tảng không tốn thêm phí (phí GuardDuty tính theo lượng dữ liệu phân tích – kiến thức phổ biến).
  • Regional: AWS khuyến nghị bật GuardDuty ở mọi Region, kể cả Region không dùng – kẻ tấn công có thể tạo tài nguyên ở Region bạn ít để ý; global service events (IAM, STS, CloudFront…) được nhân bản xử lý ở mọi Region đã bật.
  • Extended Threat Detection: tự bật, không tốn thêm phí – nối nhiều sự kiện rời rạc thành một attack sequence (tấn công nhiều giai đoạn) và sinh finding tương ứng.

Amazon Inspector: quét lỗ hổng tự động và liên tục

Amazon Inspector là dịch vụ vulnerability management: tự động phát hiện workload và quét liên tục để tìm CVE (Common Vulnerabilities and Exposures) trong phần mềm và unintended network exposure. Mỗi vấn đề sinh một finding chi tiết kèm khuyến nghị khắc phục; khi bạn khắc phục, Inspector tự phát hiện và đóng finding.

  • Finding gửi tới EventBridge (định tuyến tới Lambda, SNS) và Security Hub CSPM.
  • Multi-account: kích hoạt cho toàn organization “một cú click” bằng delegated administrator, tự kích hoạt cho account mới.
  • Inspector thế hệ hiện tại (“Inspector v2”) thay thế Inspector Classic – bản cũ cần cài Inspector agent và chạy assessment theo lịch (kiến thức phổ biến). Đề cũ có thể nhắc “Inspector agent”.
Bẫy thường gặp
  • EC2 không được quét agent-based ⇒ kiểm tra instance có SSM Agent chạy và được Systems Manager quản lý (managed instance), có instance profile phù hợp (chi tiết IAM: kiến thức phổ biến).
  • Inspector chỉ tìm lỗ hổng, không tự vá. Vá hàng loạt ⇒ Systems Manager Patch Manager (Bài 41).
  • Quét image ECR “basic scanning” là của chính ECR (Bài 34); “enhanced scanning” liên tục, gồm cả gói ngôn ngữ ⇒ do Inspector cung cấp.
Mẹo thi (Exam Tip)
  • “Continuously scan EC2 instances and container images for software vulnerabilities (CVEs)” ⇒ Amazon Inspector.
  • “Identify EC2 instances with unintended network exposure / reachable ports from the internet” ⇒ Inspector (network reachability).
  • “Scan Lambda functions’ dependencies for vulnerabilities” ⇒ Inspector Lambda scanning.

Amazon Macie: tìm dữ liệu nhạy cảm trong S3

Amazon Macie là dịch vụ data security dùng machine learning và pattern matching để phát hiện dữ liệu nhạy cảm, cho thấy rủi ro bảo mật dữ liệu và hỗ trợ tự động bảo vệ. Phạm vi là dữ liệu trong Amazon S3 (general purpose bucket).

Đánh giá bảo mật bucket

  • Khi bật, Macie tự tạo và duy trì inventory mọi S3 general purpose bucket.
  • Đánh giá liên tục quyền truy cập & bảo mật: bucket public, chia sẻ với account khác, cài đặt mã hóa…
  • Phát hiện vấn đề (vd bucket vừa thành public) ⇒ sinh policy finding.
  • Dashboard thống kê: số bucket public, chia sẻ, số object Macie phân tích được…

Phát hiện dữ liệu nhạy cảm

  • Automated sensitive data discovery: liên tục đánh giá inventory, lấy mẫu object đại diện để phân tích – tầm nhìn rộng, chi phí thấp.
  • Sensitive data discovery job: phân tích sâu, có mục tiêu – chọn bucket, độ sâu lấy mẫu, tiêu chí object; chạy một lần hoặc định kỳ.
  • Tìm thấy ⇒ sinh sensitive data finding.
  • Managed data identifiers: tiêu chí dựng sẵn của Macie, phát hiện danh sách lớn và ngày càng tăng các loại dữ liệu nhạy cảm cho nhiều quốc gia: PII (tên, địa chỉ, số hộ chiếu…), dữ liệu tài chính (số thẻ tín dụng, tài khoản ngân hàng), credential (private key, AWS secret key).
  • Custom data identifiers: bạn định nghĩa bằng regex, tùy chọn kèm keyword và quy tắc khoảng cách (proximity) – vd mã nhân viên, mã hợp đồng nội bộ.
  • Allow lists: văn bản/pattern Macie bỏ qua – vd tên người đại diện công khai, số điện thoại công khai, dữ liệu mẫu để test.
  • Mỗi finding có severity, thông tin tài nguyên, cách/thời điểm phát hiện; publish tới EventBridge và Security Hub CSPM.
  • Multi-account: Macie administrator quản lý qua AWS Organizations (bật Macie cho member) hoặc lời mời.
  • Giá: theo số bucket được đánh giá, số object được monitor cho automated discovery, và lượng dữ liệu được phân tích; 30 ngày free trial (gồm đánh giá bucket và có thể gồm automated discovery, không gồm discovery job). Nếu object mã hóa bằng customer managed KMS key, Macie cần quyền dùng key (và có thể phát sinh phí KMS).
Mẹo thi (Exam Tip)
  • “Identify S3 buckets/objects that contain PII / credit card numbers”, “GDPR/HIPAA data discovery in S3” ⇒ Amazon Macie.
  • “Notify when Macie finds sensitive data” ⇒ Macie finding ⇒ EventBridge ⇒ SNS/Lambda (vd chuyển object sang bucket cách ly).
  • “Detect a proprietary data pattern (employee ID format)” ⇒ custom data identifier (regex).

AWS Security Hub CSPM và Amazon Detective

AWS Security Hub Cloud Security Posture Management (CSPM) – trước đây gọi tắt là AWS Security Hub – cung cấp cái nhìn toàn diện về trạng thái bảo mật trên AWS và giúp đánh giá môi trường theo chuẩn bảo mật ngành và best practice. Nó thu thập dữ liệu bảo mật xuyên account, xuyên dịch vụ AWS và sản phẩm bên thứ ba – một “single pane of glass”.

Security Hub CSPM làm gì

  • Security standards (mỗi chuẩn gồm nhiều security control): AWS Foundational Security Best Practices (FSBP) do AWS phát triển, CIS AWS Foundations Benchmark, PCI DSS, NIST. Chạy kiểm tra liên tục ⇒ sinh control finding và tính security score.
  • Cần AWS Config: phần lớn control dùng service-linked AWS Config rules ⇒ phải bật AWS Config và ghi lại (record) tài nguyên. (Config rules không bị tính phí nếu chỉ do chuẩn Security Hub kích hoạt; config item vẫn tính phí.)
  • Nhận finding từ GuardDuty, Inspector, Macie, Firewall Manager, IAM Access Analyzer… và partner (APN), chuẩn hóa theo AWS Security Finding Format (ASFF), tương quan và ưu tiên.
  • Tự động hóa: automation rules tự sửa/suppress finding theo tiêu chí; tích hợp EventBridge và custom actions để gửi finding tới ticketing hoặc hệ thống tự khắc phục.
  • Regional: chỉ nhận và xử lý finding trong Region đã bật; chỉ tổng hợp finding sinh ra sau khi bật (không hồi tố). Muốn đủ kiểm tra CIS ⇒ bật ở mọi Region được hỗ trợ.
  • Cross-Region aggregation: chọn một home Region (trước gọi là aggregation Region) và các linked Region ⇒ finding, insight, control status, security score được nhân bản về home Region; cập nhật đồng bộ hai chiều; không tốn thêm phí.
  • Multi-account: delegated administrator qua Organizations; central configuration cho phép admin cấu hình chuẩn/control cho nhiều account và Region.
  • 30 ngày free trial khi bật lần đầu.

Amazon Detective – điều tra nguyên nhân gốc

Amazon Detective giúp phân tích, điều tra và nhanh chóng xác định root cause của security finding hoặc hoạt động đáng ngờ. Detective tự thu thập log từ tài nguyên AWS, rồi dùng machine learning, phân tích thống kê và lý thuyết đồ thị để dựng visualization phục vụ điều tra nhanh – bạn không phải tự tổ chức dữ liệu, viết query hay tinh chỉnh thuật toán.

  • Nguồn dữ liệu: sự kiện theo thời gian (đăng nhập, API call, network traffic) từ CloudTrail và VPC Flow Logs, cộng finding GuardDuty; tích hợp Amazon Security Lake (CloudTrail, VPC Flow Logs, EKS audit log) để truy vấn raw log.
  • Behavior graph: tập dữ liệu liên kết đã trích xuất và phân tích từ một hoặc nhiều account; account bật Detective là administrator của behavior graph; tích hợp Organizations.

Tóm tắt ghi nhớ

Những điều phải nhớ
  • Chặn: WAF (L7, HTTP) – Shield (DDoS) – Firewall Manager (áp tập trung). Phát hiện: GuardDuty (mối đe dọa), Inspector (CVE), Macie (PII trong S3). Tổng hợp: Security Hub CSPM. Điều tra: Detective.
  • WAF gắn được CloudFront, ALB, API Gateway REST API, AppSync, Cognito user pool, App Runner, Verified Access, Amplify – không NLB/EC2. Web ACL CloudFront ở us-east-1 (Global). Rule đánh giá theo priority; Allow/Block terminating, Count không; default action Allow/Block; block mặc định trả 403.
  • WCU: web ACL tối đa 5.000, giá cơ bản gồm 1.500; rule group tối đa 5.000, capacity cố định.
  • Rate-based rule: window 60/120/300/600 s (mặc định 300), limit tối thiểu 10, aggregate theo IP / forwarded IP / custom keys / count all; action ≠ Allow; scope-down statement.
  • Shield Standard: miễn phí, tự động, L3/L4. Shield Advanced: trả phí, chỉ tài nguyên chỉ định (CloudFront, Route 53, Global Accelerator, EIP ⇒ EC2/NLB, ALB, CLB); SRT (cần Business/Enterprise Support), proactive engagement (cần health check), cost protection (service credit), automatic L7 mitigation (150 WCU), bao phí WAF chuẩn.
  • Firewall Manager: cần Organizations + admin account + AWS Config; chính sách WAF, Shield Advanced, SG, NACL, Network Firewall, DNS Firewall; tự áp cho account/tài nguyên mới.
  • GuardDuty: CloudTrail management events + VPC Flow Logs + DNS logs qua luồng độc lập (không cần bật); protection plans S3/EKS/Runtime/Malware/RDS/Lambda; severity Low 1–3,9, Medium 4–6,9, High 7–8,9, Critical 9–10; phản ứng bằng EventBridge.
  • Inspector: EC2 (SSM Agent hoặc agentless snapshot), ECR enhanced scanning, Lambda; quét liên tục khi có CVE mới; risk score điều chỉnh CVSS theo ngữ cảnh.
  • Macie: chỉ S3; policy finding (bucket) + sensitive data finding; managed/custom data identifiers, allow lists; automated discovery (lấy mẫu) vs discovery job (sâu, một lần/định kỳ).
  • Security Hub CSPM: FSBP, CIS, PCI DSS, NIST; ASFF; cần AWS Config; cross-Region aggregation miễn phí; automation rules. Detective: behavior graph, tới 1 năm dữ liệu, root cause.

  3. Update the security group of the ALB to deny traffic that contains SQL statements.
  4. Subscribe to AWS Shield Advanced and enable proactive engagement.
Đáp án B. AWS WAF kiểm tra request HTTP ở Layer 7 và gắn trực tiếp được vào ALB; AWS Managed Rules (Core rule set, SQL database) chặn SQLi/XSS mà không phải tự viết rule – ít vận hành nhất. A sai: GuardDuty chỉ phát hiện, không chặn request. C sai: Security Group làm việc ở L3/L4, không đọc nội dung HTTP và không có rule deny. D sai: Shield Advanced tập trung chống DDoS; proactive engagement là SRT liên hệ khi health check unhealthy, không phải chặn SQLi.
Một công ty chạy một ứng dụng web công khai trên các Amazon EC2 instance phía sau một Application Load Balancer. Đội bảo mật nhận thấy các nỗ lực SQL injection và cross-site scripting trong log ứng dụng. Công ty muốn chặn các cuộc tấn công này trước khi chúng tới được instance với LEAST operational overhead (ít công vận hành nhất). Solutions architect nên làm gì?

  2. Create a network ACL rule in the VPC of the origin to deny the attacking IP addresses.
  3. Enable AWS Shield Standard on the CloudFront distribution.
  4. Add an AWS WAF rate-based rule to the web ACL associated with the distribution, aggregate by IP address, set a limit of 100 requests in a 300-second evaluation window, add a scope-down statement for the /login URI path, and set the action to Block.
